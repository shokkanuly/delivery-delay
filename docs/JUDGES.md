# SitePulse: проверка за 3 минуты

Это маршрут демонстрации по предоставленному исследованию, а не официальный оценочный лист конкурса.
Прототип работает на синтетических данных. Ни реальный клиент, ни подписанный пилот здесь не заявлены.

[Открыть продукт](https://logistics-api-production-2e47.up.railway.app/#audit) · [README](../README.md)

| Время | Действие | Что проверяет судья |
|---|---|---|
| 0:00–0:25 | «Открыть пример отчёта»; скачать тот же CSV | Доступ без регистрации. Сохранённый расчёт явно помечен синтетическим. |
| 0:25–1:10 | Посмотреть качество и поставщиков | Из 12 строк принято 8, исключено 4; 5 поставщиков. Причины и неизвестные материалы видны. |
| 1:10–1:40 | Сравнить поставщика и материал, прочитать 95% интервал | Маленькая выборка не выдаётся за уверенный рейтинг. «—» означает отсутствие наблюдений. |
| 1:40–2:10 | Прочитать результат проверки модели | Для этого маленького CSV недостаточно истории. Нет выдуманной точности. На большей истории модель сравнивается с простым средним поставщика. |
| 2:10–2:40 | «Подставить пример» в калькуляторе, затем «Рассчитать» | 50 000 000 ₸ × 0,1% × 4 дня + 6 ч × 25 000 ₸ = 350 000 ₸. Это договорная экспозиция, не доказанная экономия. |
| 2:40–3:00 | «Печать / сохранить PDF» и [план пилота](PILOT_PROPOSAL.md) | У результата есть переносимый отчёт и следующий проверяемый шаг. |

## Вопросы, на которые можно ответить кодом

- **Зачем машинное обучение, если есть среднее?** В `ml/audit.py` модель получает те же будущие
  заказы, что и supplier-average baseline. Если она не выигрывает, риск-группы скрываются.
  Карточка поставщика остаётся доступна. На синтетическом CV преимущество небольшое: 0,669 против 0,619 PR-AUC.
- **Есть утечка будущего?** Временная граница не делит одинаковые даты заказа. Поставки, ещё не
  завершённые к границе, исключаются из обучения; признаки и словарь строятся только на обучении.
  См. `tests/test_history_audit.py` и `tests/test_features_leakage.py`.
- **Чем подтверждены нулевые двойные брони?** Ограничением `AddNoOverlap` и отдельной проверкой
  результата в `tests/test_scheduler.py`. Это свойство алгоритма, а не измерение пользы клиенту.
- **Работает ли весь процесс согласования броней?** Нет. Назначение техники реализовано;
  роли, одобрение, перенос и уведомления запланированы. Их не следует демонстрировать как готовые.
- **Есть ли реальная экономия?** Нет измеренной экономии. Калькулятор использует введённые ставки.
- **Есть ли спрос?** В репозитории нет заполненных интервью, клиентского аудита или подписанного
  пилота. Запрос команде/партнёру: один объект, история заказов и приёмок, контакт снабженца.
- **Можно загрузить клиентский CSV в публичное демо?** Нет. Railway предназначен для синтетики;
  клиентские данные — только в отдельном развёртывании в Казахстане/на сервере клиента.

## Проверка разработчиком

```bash
python -m pytest
python -m scripts.build_demo_report --check
python run.py
```

Для CSV-аудита через API нужен `SITEPULSE_ADMIN_KEY`; ключ не публикуется и не встроен в HTML.
Публичный пример — статический JSON, вычисленный тем же доменным кодом, что и защищённая загрузка.
Его `source_sha256` позволяет проверить точные байты скачиваемого CSV.

Если Railway недоступен: локальный запуск из README и тот же пример дают тот же отчёт.
[Снимок расчёта](../static/samples/audit_report_synthetic.json) можно прочитать прямо в GitHub.
